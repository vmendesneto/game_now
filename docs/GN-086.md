# GN-086 — CPU e memória em múltiplas transcrições

O benchmark usa o pipeline existente GN-041/GN-043 com **dois ou mais workers independentes** e buffers PCM limitados, em vez de simular simultaneidade somando execuções sequenciais. A programação é concorrente via asyncio.to_thread; o campo \`max_overlapping_inferences\` registra a simultaneidade observada, que pode ser 1 dependendo do ambiente.

## Experimento reprodutível

Sem modelos, fontes externas, Windows ou inferência ASR (teste da instrumentação):

\`\`\`bash
python -m scripts.benchmark_gn086 --engine synthetic --sources 2 --seconds 6
python -m pytest -q tests/test_gn086_benchmark.py
\`\`\`

**Para medir modelos verdadeiros em CPU**, instale \`requirements-asr.txt\` e use exclusivamente WAV local 16 kHz, mono, PCM s16le, **de uso autorizado**:

\`\`\`bash
python -m scripts.benchmark_gn086 --engine real --wav audio-permitido.wav --sources 2 --model tiny --cpu-threads 2 --window-ms 2000 --overlap-ms 500 --buffer-seconds 3
\`\`\`

Use \`--model base\` para comparação no **mesmo computador**, reiniciando o processo a cada variante. A entrada é reproduzida simultaneamente em fontes isoladas para comparar sobrecarga, **não mede diversidade entre duas rádios**. Há um teste opt-in com fala pt-BR gerada localmente por eSpeak, dois modelos Whisper reais \`tiny\` independentes e FFmpeg para normalizar PCM, no workflow \`ASR pt-BR CPU real\`. Só classificar como evidência real depois da CI confirmar o resultado.

## Saída e interpretação

O JSON expõe: total de chamadas ao modelo, paralelismo efetivo, tempo de parede, tempo de CPU do processo, CPU equivalente a um núcleo (pode ultrapassar 100%), throughput em segundos de PCM agregado/tempo de parede, teto do ring buffer por fonte, high-water RSS do **processo inteiro** quando suportado (Linux/macOS) e pico de alocações Python por tracemalloc (exclui alocações nativas). \`process_peak_rss_mb\` pode ser \`null\` em Windows sem um coletor RSS nativo; não confundir o valor tracemalloc com memória total de Whisper.

A configuração inicial conservadora permanece \`tiny\`, \`2\` threads/fonte, janela 2s, sobreposição 0,5s e ring de 3s. Testes de sobrecarga **não substituem** metas práticas de latência: compare \`throughput_audio_seconds_per_wall_second\` à quantidade de fontes e observe pressão de RAM e atraso no Windows real. Sem prova real de CPU Windows ou partida de 90 minutos, não fixar limites nem alegar acurácia, estabilidade, velocidade sustentada ou capacidade de produção. O modo synthetic usa apenas trabalho artificial em SHA-256 e **não é reconhecimento de voz**.

Nenhum PCM é enviado para a API, navegador ou gravado pelo benchmark. Nunca registrar o texto de uma fonte real no resultado. GN-083 e GN-085 continuam abertas.
