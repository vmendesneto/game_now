## Processar um arquivo local permitido

1. Cadastre a partida com equipes, direção de ataque e escalações no SQLite (opção --match-id) ou forneça um objeto JSON do modelo Match (opção --match-json).
2. Disponibilize **somente uma amostra local autorizada** de no máximo 600 segundos: WAV PCM s16le mono 16 kHz ou PCM bruto no mesmo formato. Esse primeiro modo recebe **somente arquivo local**. Há também um modo adicional de **transcrição direta de uma transmissão pública autorizada**, descrito abaixo; nenhum dos modos salva PCM em disco.
3. Instale o ASR opcional: pip install -r requirements-asr.txt. Execute:

~~~powershell
.\.venv\Scripts\python.exe -m scripts.gn083_audit --wav .\amostra_autorizada.wav --match-id ID_DA_PARTIDA --source-id youtube-083 --permission-confirmed --model tiny --output .\relatorio083.json
~~~

Troque --wav por --raw-pcm para PCM bruto. A entrada é processada em chunks, usando GN-040/GN-041 e o vocabulário da escalação, sem persistir PCM. O relatório é **diagnóstico**, não altera o placar nem a bola no SQLite. Não comite mídia ou transcrições privadas. --include-text permite incluir o texto reconhecido no relatório local; por padrão é omitido.

Para avaliar apenas interpretação textual, **sem mídia nem ASR**, execute:

~~~powershell
.\.venv\Scripts\python.exe -m scripts.gn083_audit --transcripts .\transcricoes.json --match-id ID_DA_PARTIDA --output .\relatorio083.json
~~~

Exemplo de transcricoes.json (tempo relativo ao começo do áudio):

~~~json
[
  {"source_id":"youtube-083","sequence":0,"start_seconds":0,"end_seconds":6,"text":"Azul com a bola no meio-campo pela direita"}
]
~~~

A análise reutiliza GN-050–055: categoria, equipe e jogador **mencionados**, posse **somente se explícita**, região 5×3 e evento. Pistas ausentes/ambíguas permanecem null. Um jogador mencionado **não** é automaticamente o portador da bola.

## Transcrição direta do YouTube (sem gerar arquivo WAV)

A captura física de **300 segundos / 9.600.000 bytes / 600 blocos** já foi validada no Windows. **Não há necessidade de repetir o diagnóstico**. Para fazer um novo processamento (ASR, categorias, entidades, eventos e regiões) do **fluxo de uma fonte autorizada**, utilize o mesmo caminho seguro de ingestão do projeto:

~~~powershell
.\.venv\Scripts\python.exe -m scripts.gn083_audit --youtube-url "https://www.youtube.com/watch?v=Ls4qkPrh4Tk" --match-id ID_DA_PARTIDA --source-id youtube-083 --yt-dlp ".\.venv\Scripts\yt-dlp.exe" --seconds 300 --permission-confirmed --model tiny --output .\relatorio083.json
~~~

Esse comando **não executa app.youtube_capture --seconds**; ele inicia o fluxo somente para efetuar reconhecimento de voz. GN-031/GN-090 entregam PCM 16 kHz em memória a GN-041, que forma janelas sobrepostas, passa-as ao Whisper em thread de trabalho e entrega texto aos classificadores já existentes. O áudio bruto não é salvo, servido ao navegador ou incluído no relatório.

O relatório informa duração/bytes processados e audio_duration_complete, além das hipóteses extraídas. Se a transmissão terminar antes dos 300 segundos, audio_duration_complete é false: **não** tratar uma amostra curta como processamento completo. A reprodução do conteúdo de terceiro exige permissão de uso; acesso público ao vídeo não é confirmação automática.

Para gerar métricas reais, anote um gabarito **independente** para a mesma janela e acrescente --reference .\gabarito083.json. **Sem gabarito, o CLI deixa as métricas null.** Para inspecionar localmente a transcrição (possivelmente sensível), use --include-text, evitando compartilhar o arquivo gerado.

### Incompatibilidade corrigida: faster-whisper 1.2.1 + PyAV 19.0.2

O autoteste **real no Windows 11/Python 3.12** retornou `TypeError: open() got an unexpected keyword argument 'metadata_errors'`. O pacote `faster-whisper==1.2.1` passa `metadata_errors` para `av.open`, mas `av==19.0.2` (instalado automaticamente por não haver limite superior na dependência transitiva) não aceita esse argumento. Há relato idêntico em https://github.com/SYSTRAN/faster-whisper/issues/1589.

O projeto passou a fixar `av==17.1.0` no `requirements-asr.txt`, release com suporte ao argumento e wheel Windows CPython 3.12 (ABI estável). Para corrigir a instalação existente, em Prompt de Comando na pasta do projeto:

~~~bat
git pull --ff-only
.\.venv\Scripts\python.exe -m pip install -r requirements-asr.txt
.\.venv\Scripts\python.exe -m pip show av
.\.venv\Scripts\python.exe -m scripts.gn083_asr_check --model tiny
~~~

Só se o autoteste retornar `"ok": true`, passar à transcrição de uma fonte autorizada usando a opção `--seconds 6` indicada acima; depois aumentar para 300 segundos. A execução do autoteste após alterar PyAV ainda precisa ser **confirmada pelo usuário**; CI sintética não equivale a ensaio Windows real. Não reenviar o diagnóstico antigo de captura PCM.


## Falha HTTP 403 no teste de 300 segundos (2026-11-11)

**Evidência física nova:** o usuário confirmou que `faster-whisper==1.2.1` + `av==17.1.0` passaram no autoteste CPU (`ok=true`). O diagnóstico autorizado de **6 segundos** de Cruzeiro x Bahia com modelo `tiny` captou 192.000 bytes PCM, gerou uma janela textual e deixou atleta/posse/zona/evento desconhecidos (sem gabarito). A tentativa de **300 segundos com modelo `base`** terminou com `Remote media request failed (upstream_http_403)`. Isso é resposta de acesso negado na origem do fluxo (não erro de modelo), **sem comprovação de quanto PCM chegou antes da recusa**.

No modo padrão, a GN-083 lê um bloco PCM, interrompe a leitura durante a inferência CPU e só depois continua capturando. Isto pode prejudicar fontes de mídia que não tolerem pausa, mas **não está demonstrado que causou o HTTP 403**. Para diagnosticar uma fonte de uso autorizado, há agora `--capture-first`: separa captação e inferência, mantém na memória no máximo 600 segundos PCM (19,2 MB), nunca salva áudio e nunca tenta contornar um acesso negado ou repetir automaticamente um 403. Se a origem recusar, a mensagem informa quantos segundos PCM chegaram antes do erro.

Opcionalmente, **após verificar que a fonte está acessível e autorizada**, testar um trecho intermediário curto com o modelo `base` sem repetir os 300 segundos:

~~~bat
.\.venv\Scripts\python.exe -m scripts.gn083_audit --youtube-url "https://www.youtube.com/watch?v=Ls4qkPrh4Tk" --match-id cruzeiro-bahia-gn083 --yt-dlp ".\.venv\Scripts\yt-dlp.exe" --seconds 30 --model base --capture-first --permission-confirmed --diagnose-asr --include-text --output relatorio083-30s.json
~~~

Se houver novo `upstream_http_403`, não fazer retentativas automáticas, não usar cookies ou técnicas para burlar acesso; buscar uma gravação local ou outra transmissão com autorização explícita. Se os 30 segundos funcionarem, então é possível solicitar 300 segundos com a mesma opção `--capture-first`. Nenhuma métrica de precisão está disponível sem gabarito independente.


## GN-083 — detector contínuo de fases (subescopo técnico, 2026-11-11)

A implementação de regras **não substitui a validação com narração real**. O
detector em app/match_start_detection.py usa estados pre_game, probable_start,
in_play, half_time e second_half; confiança none/low/medium/high significa
força de evidência de regras, **não probabilidade calibrada**. Tempos são
relativos à captura de áudio, sem presumir horário oficial de apito.

- Futuro ("a bola vai rolar", "vai começar"), propaganda, escalações,
  análises, replay e gols históricos não iniciam a partida.
- Apito/início narrado inicia estado provável, não libera o campo sozinho.
  Exige primeira jogada explícita; se o apito não for transcrito, três janelas
  de jogo atual com três pistas distintas confirmam de forma
  conservadora. Duplicação próxima de janela ASR não acrescenta evidência.
- Fim inequívoco da primeira etapa, ou dois indícios distintos de intervalo,
  suspende a bola. Reinício do segundo tempo exige confirmação de jogada.
- app/gn083_live.py monitora YouTube/PCM e executa ASR em worker contínuo
  com fila de até ~40 segundos; se o CPU não acompanhar, informa erro, sem
  descartar amostras silenciosamente. Não há limite de duração por padrão.
- O servidor mantém uma **prévia efêmera**, somente local, com API
  POST /api/matches/{id}/live/observation e GET /api/matches/{id}/live/preview.
  A interface alterna para campinho de prévia ao selecionar uma partida com
  monitor ativo. Apenas após confirmação de início e pista explícita de
  posse/equipe/zona o campo mostra região, por no máximo oito segundos após
  a evidência. Não grava posição, placar, eventos ou relógio em SQLite; não
  reproduz o áudio nem envia PCM para o navegador. A idade real do lance em
  relação à transmissão **ainda não foi medida**.
