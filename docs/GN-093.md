# GN-093 — proteção de acesso ao Game Now

## Política de segurança

**Por padrão, o aplicativo continua local**: `iniciar_windows.bat` e `python -m scripts.serve_secure` usam `127.0.0.1`; o middleware bloqueia clientes não-loopback, hosts locais não permitidos e origens cruzadas em mutações e WebSockets. Não expor o processo com `--host 0.0.0.0` apenas por mudar a linha de comando.

**Modo LAN explicitamente habilitado** (operador único): `GAME_NOW_REMOTE_ACCESS=1` exige um token de acesso aleatório com 32+ caracteres ASCII imprimíveis sem espaços, um segredo **independente** de 32+ caracteres para assinar sessões, e tráfego HTTPS/WSS de ponta a ponta. Configuração inválida impede iniciar. O browser entra em `/_auth/login`; recebe cookie de sessão assinado, expira em oito horas, `Secure; HttpOnly; SameSite=Strict`, sem token no cookie ou na URL. APIs podem usar `Authorization: Bearer TOKEN`. Mudanças e WebSockets com cookie exigem `Origin` da própria origem. Login/saída e conteúdo privado não são disponibilizados por HTTP sem TLS.

### Operação no Windows (somente rede de confiança)

1. Gere **dois valores aleatórios separados** no PowerShell, sem colocá-los no histórico, arquivos versionados ou prints:
   ```powershell
   $env:GAME_NOW_REMOTE_ACCESS = "1"
   $env:GAME_NOW_ACCESS_TOKEN = ([Convert]::ToBase64String([Security.Cryptography.RandomNumberGenerator]::GetBytes(32)))
   $env:GAME_NOW_SESSION_SECRET = ([Convert]::ToBase64String([Security.Cryptography.RandomNumberGenerator]::GetBytes(32)))
   ```
2. Providencie certificado HTTPS e chave privada adequados para o endereço DNS/IP usado pelo navegador, confiáveis no cliente. Guarde-os fora do repositório e com ACL restrita.
3. Inicie **explicitamente** com TLS (apenas LAN confiável, firewall restritivo):
   ```powershell
   .\.venv\Scripts\python.exe -m scripts.serve_secure --host 0.0.0.0 --port 8443 --tls-cert "C:\segredos\server.crt" --tls-key "C:\segredos\server.key"
   ```
4. Acesse `https://<IP-ou-DNS>:8443/_auth/login`, informe o token pelo formulário, teste a interface e o WebSocket. Um certificado inválido/não confiável **não deve** ser contornado. Não reutilize o token como segredo de sessão. Para sair: envie POST `/_auth/logout` na própria origem ou apague cookies. Reiniciar com segredo diferente invalida os cookies anteriores.
5. Para voltar ao modo local, remova as três variáveis e reinicie o servidor via `iniciar_windows.bat`. Mesmo no modo remoto, o sistema continua **sem integração automática de áudio na interface**, nem reproduz mídia.

### Matriz de ameaças e limitações

| Ameaça | Mitigação implementada | Limite operacional |
| --- | --- | --- |
| API/SQLite acessíveis de fora por bind acidental | Rejeição de peer remoto sem opt-in | Port-forward/SSH local pode parecer loopback; firewall é obrigatório |
| Interceptação do token e dos textos | HTTPS/WSS obrigatório no modo remoto; cookie Secure | Certificado válido e distribuição segura do token são responsabilidade do operador |
| Leitura/alteração sem autenticação | Bearer ou sessão HMAC; token >=32 caracteres; endpoints estáticos protegidos | Token único (sem papéis, revogação individual ou limite de tentativas); LAN de confiança, **não publicar diretamente na Internet** |
| CSRF e sequestro de WebSocket | SameSite=Strict e Origin em mutações/WS; sem token em query | Proxies e mudança de Origin devem ser testados; não habilitar proxy headers arbitrários |
| DNS rebinding no modo local | Host allowlist e bloqueio de peer remoto, checagem de Origin | Aplicativos locais maliciosos, IP forwarding e extensões de navegador permanecem fora do escopo |
| Vazamento no log | API grava método/caminho sem corpo/query; token não é impresso pelo middleware | Proteja a shell, o ambiente e backups; operadores podem ler seu próprio processo |
| Falha ou roubo de sessão | HMAC-SHA256 e validade de 8h, logout e rotação do segredo | Sem sessão persistente, revogação por usuário ou auditoria de login |

**Evidência automatizada:** testes HTTP e WebSocket com TestClient em HTTPS simulado, rejeição de rede/HTTP, configuração inválida, cookie/CSRF/Origin e runner que recusa bind sem TLS. TestClient **não valida um handshake TLS de socket, certificado externo, firewall, proxy, Windows físico ou testes de penetração**. Antes de qualquer exposição à Internet, faça revisão independente, autenticação de usuários, rate limit, trusted proxy e infraestrutura gerenciada. GN-085 continua pendente; GN-093 não autoriza exposição pública irrestrita.
